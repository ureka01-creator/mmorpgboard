# 1.0 품질 점검과 제작 기준 재설정

사용자 피드백: “퀄이 너무 낮군.” 기능 검증 통과를 만족스러운 게임 품질로 해석하지 않는다. 현재 모험은 진행 가능한 시제품이며, 화면과 연출은 목표 완성도에 미치지 못한다.

## 현재 화면에서 확인한 문제

- 장소는 세밀한 그림이지만, 실제 이동 가능 공간은 별도의 직사각형 격자다. 건축물·기둥과 장애물 표시가 정밀하게 맞지 않아 장소 안에서 걷는 느낌이 약하다.
- 캐릭터는 정지 전신 이미지다. 이동 때 DOM을 다시 그리므로 걷는 동작이나 경로를 따라 움직이는 과정이 없다. 공격·피격·시전·쓰러짐 동작도 없다.
- 전투는 규칙 결과와 피해 숫자를 바로 표시한다. 적의 이동과 여러 공격이 한 번에 반영되어 누가 누구에게 무엇을 했는지 시각적으로 읽기 어렵다.
- 주사위는 결과 표시와 회전 효과가 있지만 판정이 일어나는 장면과 연결되는 연출이 약하다.
- 파티와 대화의 기존 초상화가 새 전신 캐릭터와 정확히 일치하지 않는다.
- 하단 메뉴는 조작 가능하지만 아이콘, 대상 미리보기, 상태 효과, 선택 피드백이 부족해 게임 고유의 시각적 언어가 약하다.
- 한 임무의 대화 선택은 선금과 신뢰를 바꾸지만 실제 장소와 해결 경로의 분기가 아직 적다. 시각 개선만으로 이야기의 깊이가 생기지는 않는다.

## 다음 제작 단위: 한 전투 장면의 완성도

기능과 장소 수를 늘리기 전에 작은 유적 교전 하나를 기준 장면으로 만든다. 사용자는 실제 3D 공간과 움직이는 캐릭터를 선택했다. 다음 범위를 이동과 공격까지로 한정했으므로, 대화·파티·임무 추가를 보류한다. 1.1은 리깅된 캐릭터의 실제 걷기, 경로 이동, 공격·피격·쓰러짐과 카메라 조작을 연결하는 동작 검증판이다. 모델은 임시 스타일의 자산이며 목표 시안의 사실적인 아트 수준은 별도 제작/확보가 필요하다.

공통 완성 기준:

1. 캐릭터·배경·초상화의 시점, 색과 인물이 일치한다. 실제 통로가 화면에서 명확히 읽힌다.
2. 선택한 캐릭터를 카메라와 강조 표시로 찾을 수 있다. 캐릭터는 실제 경로를 따라 이동하며 벽을 가로지르는 직선 보간을 하지 않는다.
3. 이동, 대기, 공격/시전, 피격, 쓰러짐을 구분한다. 그림 자체의 전체 이동이나 화면 흔들림을 캐릭터 애니메이션의 대체물로 취급하지 않는다.
4. 공격자 → 대상 → 판정 → 동작 → 피해/상태 변화가 차례로 보인다. 여러 적 행동도 순서대로 보이며 스킵/빠르게 보기와 중복 입력 방지가 있다.
5. 행동을 고르기 전에 AP 비용, 도달 경로, 사거리, 시야 차단과 대상을 예측할 수 있다. 전투 로그를 읽어야만 결과를 알아보는 화면을 피한다.
6. UI의 기본·선택·사용 불가·위험 상태를 일관되게 표현한다. 태블릿 화면에서 파티·상태·행동이 장면을 과도하게 가리지 않는다.
7. 이전과 같은 저장 안정성과 규칙 검증을 유지한다. 연출 스킵이나 새로고침으로 피해가 중복 적용되거나 판정이 재추첨되지 않는다.

## 구현 방식에 따른 필수 작업

실제 3D: WebGL 렌더러, 카메라와 조명, 장소의 메시/충돌, 리깅된 캐릭터와 걷기·공격·시전 애니메이션, 애니메이션 전환과 적 행동 연출이 필요하다. 정지 생성 이미지를 3D 모델로 간주하지 않는다. 품질을 갖춘 모델과 애니메이션의 확보·제작이 주요 작업이다.

2D 배경 + 움직이는 캐릭터: 장면과 캐릭터의 공통 투영·크기, 방향별 실제 애니메이션 프레임 또는 리깅된 모델 렌더링, 가림과 깊이 정렬, 카메라와 화면 좌표 변환, 배경에 정확히 맞춘 이동/시야 영역이 필요하다.

두 방식 모두 HTML은 실행 화면을 담을 수 있다. 현재의 HTML DOM 배치만으로 요구되는 공간과 동작의 품질을 갖추었다고 주장하지 않는다.
