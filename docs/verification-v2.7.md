# 2.7 이동·검격 연결 검증

2026-10-14. 사용자가 이동·공격이 여전히 어색하다고 지적하여 실제 게임 렌더러로 8방향의 대기·8개 보행·준비·타격·복귀 자세를 확대 검사했다. `scripts/review_sprite_motion.py`로 재현한다. 확대 화면은 진단용 직교 카메라로 표시한 실행 캐릭터이며 실제 던전 플레이 스크린샷과 구분한다.

## 발견과 수정

1. 발과 검을 포함한 전체 그림 높이를 각 안내 자세에 맞추면서 픽셀당 월드 크기가 보행 중 최대 24.972%, 공격 중 최대 26.618% 달라졌다. 방향별 보행 중간값을 이동·공격 전체에 적용하여 계산상의 확대율 변화는 반올림 오차 범위로 제한했다. 원래 값은 `guideWorldHeight`로 보관한다. 그림 자체의 비례 차이를 없앴다는 뜻은 아니다.
2. 공격 중 같은 이동 거리에 대해 보행 위상이 두 배 빨리 진행되고 있었다. 같은 2.24m 주기를 사용하며 공격 그림 동안 보행 발소리 카운터를 진행하지 않는다.
3. N·NW·W의 2번 원화는 검을 든 자세인데 타격 시점에 사용했다. 이 세 방향은 3번 원화가 베기이며, S·SE·E·NE·SW는 2번이 베기다. 방향별 실제 베기를 물리 타격 시점에 맞추고 검을 내린 대기 자세로 복귀한다. 적은 준비 중 든 검을 공격 시작에 다시 내리지 않는다.
4. 마지막 명중 때 논리 상태가 즉시 승리/대기로 바뀌어 베기 그림이 사라졌다. 피해·승리는 즉시 확정하되 남은 0.40초의 베기·복귀를 화면에 표시한 뒤 승리창을 보여 준다. 그동안 조작은 비활성화되며 초기화하면 대기 중인 결과 표시도 취소된다.

## 검증

- 기존 엔진 17개 검사: 이동·충돌·경로·검격·회피·피해·승리·사망·재시작. 전투 규칙과 피해 시점은 바꾸지 않았다.
- 자산/동작 검사: 원본 PNG 10개와 자세 안내의 SHA256, 160개 영역, 8방향, 모든 보행·공격 그림의 동일 확대율, 방향별 베기·복귀·적 준비와 공격의 연결.
- Chromium 실제 GPU와 동작: 투명 그림, 64개 보행, 공격·회피·발 기준점·독립 UV·정지·초기화·로딩 실패. 추가로 동일 거리의 공격/보행 위상, 적 준비→타격, 실제 엔진 첫 명중과 베기 그림, 마지막 명중의 베기 유지와 복귀를 검사했다.
- 실제 입력: 키보드·바닥 이동·충돌·두 손가락 이동/공격·이동 중 회피·승리와 결과창·초기화. 1024×768, 768×1024, 390×844에서 터치 조작과 스크롤 없는 배치를 확인했다.

## 남은 아트 문제

이동·공격의 프로그램 확대율을 고쳐도 대기·보행·공격 그림의 얼굴/상체/장비 비례와 실루엣 차이는 남아 있다. 일부 방향의 발 교대가 약하고, 준비→타격→복귀 사이 중간 그림이 부족하다. 코드를 고쳤다고 자연스러운 원화까지 완성된 것은 아니다. 다음 아트 작업은 같은 신체 비례와 무기 길이, 좌우 발 접지, 검 궤적을 유지하는 중간 원화 제작이다. 겹쳐 보이는 크로스페이드로 자세 차이를 숨기는 방식은 사용하지 않는다.

검사 환경은 Chromium 소프트웨어 WebGL이다. 실제 iPad Safari 성능과 주관적인 움직임 품질은 별도의 사용자 플레이 확인이 필요하다. 이전 기록은 [2.6](verification-v2.6.md)에 보관한다.
