# 2.13 연속 표시와 이동·공격·회피 전환

승인된 2.8 원본 PNG 10개와 warrior.json은 변경하지 않는다. 얼굴·갑옷·비례·배경·카메라 방향과 전투 규칙을 유지한다. 이번 범위는 이동·공격·회피의 연결과 표시 안정성이다.

## 수정

- 전투·충돌은 기존 60Hz 고정 시뮬레이션을 유지한다. `arena-presentation.mjs`는 이전/현재 상태 사이에서 매 표시 프레임의 위치·거리·동작 시간을 구한다. 판정 시점에는 명중 자세를 즉시 표시하고, 승리 시 마지막 베기를 마친다. 입력이나 피해를 예측해 새로 계산하지 않는다.
- 대기에서 달리기 12자세 각각으로 연결되는 수치 변위장을 준비했다. 전체 240개 연결이며 원본 그림을 다시 저장하지 않는다. 이동 시작·정지는 감쇠하는 연결값으로 몸·망토·발을 같은 흐름에 놓는다. 앞선 보행의 가상 중간 자세를 유지하면서 대기로 복귀한다.
- 같은 방향으로 달리다가 공격하면 45ms 동안 발을 정리하고 검을 들어 올린다. 적의 준비에는 60ms의 발 정리를 사용한다. 영웅 0.26초, 적 0.18초의 실제 명중은 유지한다. 원래부터 서 있던 공격에는 추가 지연을 붙이지 않는다.
- 기본 회피는 같은 기사의 달리기 원화를 사용하는 짧은 대시다. 이동 거리로 발동작을 진행해 달리기→회피→달리기가 이어지며, 벽에 막히면 발동작도 진행하지 않는다. 엔진의 속도·지속·무적·쿨다운은 변경하지 않았다. 이전 구르기 원본은 쓰러짐과 비교 모드에 보존한다.
- 실제 캐릭터 텍스처 복제가 끝난 뒤 모든 방향의 GPU 그림을 준비한다. 첫 방향 전환·검격·회피에서 큰 원화를 다시 업로드하지 않는다. 기존 셰이더 사전 준비도 유지한다.
- 고정된 태양/건축물의 그림자만 재사용한다. 움직이는 그림 캐릭터는 기존의 개별 바닥 그림자를 사용한다. 이 캐시에서 캐릭터의 그림자를 고정하지 않는다.
- 240개 변위장 타일은 12열로 배치해 672×1840 크기로 유지한다. 2K 텍스처 크기 안에 들어가며 수치 데이터 압축 파일은 약 6.7 MB다.

## 비교 기준

OpenNox의 공개 구현에서 [8방향 이미지와 장비 프레임](https://github.com/noxworld-dev/opennox/blob/0e78e4cd5be47c9ab34d85110f1ae21bafbfb217/src/drawable_player.go), [프레임 진행](https://github.com/noxworld-dev/opennox/blob/0e78e4cd5be47c9ab34d85110f1ae21bafbfb217/src/drawable_vector.go)을 읽어 몸·장비의 동기화와 방향 구조를 참고했다. 해당 코드와 원작 게임 자산을 실행 앱에 복사하지 않았다.

실제 화면의 수치 비교는 변경 전 실행 소스 `263950c`(2.12)와 수정 버전에 같은 엔진 입력을 넣어 수행했다. 원작 Nox를 이 환경에서 실행하거나 원작 영상과 나란히 측정한 검사는 아니다. 아래 수치를 Nox 유사성 점수로 해석하지 않는다.

[연속 영상 정면](motion-review-v2.13/direction-0.mp4) · [연속 영상 측면](motion-review-v2.13/direction-2.mp4) · [8방향 시점표](motion-review-v2.13/direction-0.png). 영상은 60fps·3초의 실제 WebGL 렌더다. 시점표의 같은 디렉터리에 direction-1~7이 있다. 변경 전/후 측정값은 baseline-2.12.json과 metrics.json에 보존한다.

## 검증

- 30/60/90/120/144/240Hz 표시 시계에서 위치는 두 실제 시뮬레이션 위치 사이에 있고 이동·보행 표본이 반복되지 않는다. 실제 앱을 120Hz 시계로 구동한 검사에서는 고정 상태 위치가 58번 반복되는 동안 표시 위치와 보행은 반복 0회였고, 정지 시에는 완전히 멈췄다. 이는 시계 모의 검사이며 기기의 실제 120fps 측정값은 아니다.
- 8방향 정지/공격 진입의 연속 화면 변화 최대값을 이전 버전과 비교한다. 정지는 기존 대비 약 0.55~0.82, 공격 진입은 약 0.81~0.86이었다. 단일 정지 그림만 비교하지 않고 전환 구간의 최대 변화량을 검사한다. 이 값은 자연스러움 점수가 아니다.
- 실제 이동/충돌 시뮬레이션의 회피 표시 378표본, 8방향 달리기 복귀와 막힌 이동의 발 진행을 검사했다. 회피 중에도 같은 승인된 방향별 기사 원화를 사용한다.
- 128개 시드·256,000 표시 프레임·234,417 고정 틱(약 65분 분량)의 무작위 입력을 모의했다. 승리 341회, 패배 32회, 새 상태 501회, 일시 정지 확인 1,152회이며 8방향과 모든 동작 상태를 포함했다. 실제 GPU의 살아 있는 결과 실루엣 검사에서 추가 작은 분리 픽셀의 최대는 11이었다. NaN/무한값·큰 몸 분리·정지 중 동작 진행은 검출되지 않았다. 이 검사는 엔진과 실제 표시 객체를 함께 구동하며 모든 프레임을 네이티브 터치로 입력한 검사는 아니다.
- 같은 GPU 장면에서 그림자를 매번 계산할 때와 캐시할 때 픽셀 오차는 0이었고 그리기 요청은 32회→23회였다. iPad 실제 프레임 성능의 수치로 해석하지 않는다.
- 실제 WebGL 컨텍스트 손실/복구를 발생시켜 게임 일시 정지와 그림자 캐시 재생성을 확인했다. 복구 뒤 그림자 기록 픽셀은 147,933개였다.
- 실제 캐릭터를 8방향·32개 대기/달리기/검격/회피 자세로 처음 표시하는 동안 뒤늦은 원화 업로드 0회, 새 셰이더 프로그램 0개였다.
- 원본 해시·17개 전투 규칙·96개 보행 연결·명중 시점·기존 발 연결 검사를 유지한다. 정지/공격 전환 검사는 독립된 원래 기준 자세 보존 검사와 분리해 수행한다.

```sh
node scripts/verify_arena.mjs
node scripts/verify_motion.mjs
node scripts/verify_sprite_flow.mjs
node scripts/verify_presentation.mjs
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_display_clock.py
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_evade_continuity.py
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_motion_stress.py
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_static_shadows.py
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_texture_warmup.py
ARENA_BASE=http://127.0.0.1:8038/ python scripts/verify_context_recovery.py
ARENA_SEQUENCE_BASELINE=docs/motion-review-v2.13/baseline-2.12.json ARENA_SEQUENCE_CURRENT=docs/motion-review-v2.13/metrics.json python scripts/verify_sequence_comparison.py
```

수치 데이터 재생성은 2.11과 같은 분석 전용 OpenCV/NumPy/SciPy/Pillow 환경에서 `scripts/build_sprite_flow.py`를 실행한다. 실제 조작/충돌/멀티터치/회피/승리/정지/초기화와 1024×768·768×1024·390×844 화면은 `verify_arena_browser.py`로 확인한다. source 오류/수치 파일 손상 재시도, 기둥 가림, 바닥 깊이, 양쪽 진입점의 승인된 아트 검사도 유지한다.

## 한계

망토는 승인된 원화 사이를 연결하는 방식이며 독립적인 천 물리 시뮬레이션은 아니다. 원화의 가림·자세 차이는 남아 있고 이 반복 검사가 모든 시각적 결함의 부재를 증명하지 않는다. Nox와 동등한 완성도나 게임 전체의 완벽함, 실제 iPad Safari 성능을 이 환경의 검사만으로 확정하지 않는다.
