# Nox 검 공격 대조와 2.14의 범위

요청 목표는 Nox와 같은 공격 동작이다. 2.14는 그 목표의 완료판이 아니다. 원작 프레임을 확인한 뒤, 기존 원화로 고칠 수 있는 잘못된 자세 순서를 먼저 수정한 버전이다.

## 실제로 확보한 자료

[공개 웹 포트](https://github.com/Carter54git/OpenNox-WASM/tree/5aea117b78b36c81442e47e14251d5bf313cff81)의 `assets/thing.bin`과 `video.idx`/`video.bag.*`에서 PlayerDraw를 읽었다. [OpenNox libs의 형식 정의](https://github.com/opennox/libs/tree/main/things)와 bag/PCX 자료를 이용해 별도 `/tmp` 분석 환경에서 몸·의복·검·방패의 프레임을 합성해 관찰했다. 색상 재질은 중립 회색으로 표시했으므로 원작의 최종 게임 색상을 재현한 이미지는 아니다.

확인한 데이터는 한손검 `SWORD_STRIKE` 6자세×8방향, 장검 `LONG_SWORD_STRIKE` 8자세×8방향이다. 각 상태는 `Slave` 방식이며 프레임 수만으로 실제 재생 시간을 정하지 않는다. 파일 해시와 확인 범위는 [기계 판독 기록](nox-attack-reference.json)에 보존한다.

Nox 웹 포트의 메뉴와 캐릭터 선택은 실행했다. 공격 플레이 촬영은 완료하지 못했다. 지도/호스트 기능을 포함한 해당 포트의 제약을 확인했고, 별도 Linux OpenNox 배포판도 이 환경에서 실행되지 않는 32비트 실행 파일이었다. 따라서 원작 공격 속도·피해 시점·연타 간격을 실제 게임 실행으로 측정했다는 주장은 하지 않는다. YouTube/일반 영상 사이트는 현재 네트워크에서 접근되지 않았다.

원작 스프라이트나 합성 참고 프레임은 저장소와 실행 사이트에 복사하지 않았다. 참조 파일은 비교 환경에만 있다.

## 확인된 차이와 이번 수정

현재 게임의 7개 공격 자세에는 준비·베기 이외에 앞으로 뻗는 자세(3), 공격 후 검을 다시 드는 자세(5)가 섞여 있었다. 2.13은 이들을 모두 순서대로 보간했다. 원작의 한 번의 준비→베기→회수 흐름과 다르게 보이는 구체적인 원인이다.

2.14의 표시 경로는 0(기존 준비)→1(당기기)→2(올리기)→4(베기)→6(원래 준비)다. 자세 3과 5를 재생하지 않으며, 새 수치 연결 `2→4`, `4→6`을 8방향 모두 추가했다. 영웅 명중 0.26초, 적 명중 0.18초와 충돌·범위·쿨다운·피해 규칙은 유지했다. 적이 이미 검을 올린 경우에는 2에서 시작해 같은 베기/회수로 이어진다. 기존 대기·걷기·회피는 유지했다.

오른쪽/뒤쪽 방향(2,4)은 준비 자세 1의 검 방향이 역전되어 불필요한 회전을 만들므로 0→2로 직접 검을 든다. 오른쪽 준비의 칼날 방향 총 이동은 기존 약 296도에서 약 63도로 줄었다. 이는 수치 연결 경로의 측정이며 Nox와의 유사성 점수가 아니다.

기존 240개 연결과 새 18개 연결을 포함한 schema 3 변위장 258개는 672×2024 텍스처에 배치한다. 승인된 2.8 PNG 10개와 `warrior.json`은 바이트 단위로 유지한다. 새 공격 시안은 갑옷과 비례 차이가 확인되어 채택하지 않았다.

## 아직 맞추지 못한 부분

- 원작의 검을 어깨 뒤로 거두는 자세와 우리 원화의 몸 앞에서 드는 자세는 다르다.
- 원작의 몸통·골반 회전, 손목 방향, 체중 이동을 기존 원화의 수치 보간만으로 같은 자세로 만들 수 없다.
- 실제 Nox 실행 영상의 시간 기준을 확보하지 못했으므로 원작과 동일한 공격 속도나 연타 리듬은 검증하지 않았다.

따라서 2.14는 잘못 끼어 있던 동작을 제거한 수정이다. 원작과 같은 전신 자세를 완성하려면 승인된 외형을 유지하는 전용 공격 자세 제작/리깅과 원작 시간 기준의 영상 대조가 남는다. 테스트 통과를 Nox와 동일한 공격 완성도로 해석하지 않는다.

칼날 방향 경로의 변경 전/후 수치는 [측정 JSON](sword-path-comparison-v2.14.json)에 남긴다. `node scripts/measure_sword_paths.mjs`로 2.13 소스와 현재 소스의 준비/회수 경로를 같은 1ms 표본 간격으로 다시 계산할 수 있다. 원작 재생 시간을 측정하는 도구는 아니다.

같은 엔진 입력으로 기록한 2.13/2.14의 실제 WebGL 화면이다. 영상은 60fps, 3초이며 캐릭터를 따라가는 검사 카메라를 사용한다. 원작 Nox와 나란히 재생한 영상이 아니다. 시점표는 공격 시작 후 같은 시각의 화면을 영상에서 그대로 추출했다. 해당 디렉터리의 direction-0~7.png는 8방향의 이동·정지·공격 진입·회피 연결을 기록한다.

실제 원작 녹화 파일을 받으면 `scripts/compare_attack_video.py --reference <로컬 영상> --reference-start <공격 시작 초>`로 원작과 실제 게임 녹화를 원래 속도 그대로 나란히 만들 수 있다. 시작 시각·무기·방향·영상 출처는 사람이 확인해야 하며 도구 자체가 유사도/완료 판정을 내리지 않는다. 도구의 실제 ffmpeg 실행은 기존 2.13 영상을 입력으로 확인했다. 이 준비가 원작 공격 재생 시간 검증을 대신하지 않는다.

## 2.14에서 완료한 검증

- 17개 전투 규칙, 원본 아트 해시, 258개 수치 연결/손·머리 앵커, 8방향 한 번의 베기와 준비 회전 상한을 통과했다.
- 실제 GPU 보행 96개 연결, 원래 기준 자세 보존, 명중·정지 검사 통과. 공격 248개 자세의 추가 분리 픽셀 최대 9로 기존 상한 25 이내였다.
- 128개 시드, 256,000 표시 표본, 234,417 고정 틱(약 65분 분량)을 모의했다. 승리 341회·패배 32회·정지 검사 1,152회, 실제 GPU 실루엣 감사의 작은 분리 픽셀 최대 8이었다. 모든 표본이 네이티브 터치 입력이나 실제 GPU 프레임인 것은 아니다.
- 실제 브라우저의 키보드·동시 멀티터치·회피·벽/기둥 충돌·일시 정지/초기화·5회 명중 승리, 1024×768·768×1024·390×844 화면 검사를 통과했다.
- 양쪽 진입점에서 PNG 원본 10개와 자세 JSON이 승인된 2.8과 동일하며 GLB 교체가 없음을 확인했다. 손상된 수치 데이터는 게임 생성 전에 거부하고 재시도 UI를 표시했다.

이 결과는 수정한 경로의 회귀 검사다. 위에 기록한 원작 전신 자세/실제 속도 대조의 미완료 상태를 바꾸지 않는다.
