# 2.9 · 철의 훈련실

기존 2.8과 별도로 동일 모델의 연속 동작과 환경 조명 일치를 검증하는 플레이 장면이다.

플레이: https://ureka01-creator.github.io/mmorpgboard/study.html?release=2.9

## 제작 범위

일러스트 프레임을 더 생성하는 방식 대신, 하나의 53관절 스킨과 연속적인 발·팔·검 궤적을 사용한다. 작은 훈련실에서 한 방향의 보행과 검격을 확대 렌더해 검토한다. 플레이에서는 전 방향으로 이동할 수 있다. 먼저 실제 3D에서 접지와 조명을 검증하며, 이 단계에서 방향별 최종 스프라이트를 양산하지 않는다.

`warden.glb`는 기존 CC0 파생 스킨의 뼈대를 유지하고 곡면 철제 흉갑·겹친 어깨 갑옷·무릎 보호대·가죽 부츠·붉은 스카프와 새 얼굴을 제작한 모델이다. 철·가죽·천·피부 등 10개 물리 재질을 사용하며, 이전 일러스트나 스튜디오 조명을 텍스처로 넣지 않았다. 원형 방패와 검도 실제 3D 메시다. 출처·기준 SHA256과 새 파일 해시는 `assets/characters/warden-sources.json`, 기존 CC0 저작자·라이선스는 같은 폴더의 `LICENSE.txt`에 보존한다.

캐릭터와 훈련실은 같은 환경광·방향광·횃불 빛을 받고 실제 그림자를 만든다. 직교 카메라로 이동 중 화면상의 크기를 일정하게 유지한다. 문과 대형 맵 확장 없이 기존 전투 엔진의 한 전투 구역과 연결 착지 공간만 표현한다. 바닥·기둥·장애물은 기존 충돌 좌표와 일치한다.

## 동작

- 보행은 실제 이동 거리와 속도로 주기를 계산한다. 빠른 이동과 느린 이동에 다른 보폭·발 들기 높이를 사용한다. 지지하는 발의 위치를 월드에 고정하고 두 관절 IK로 다리를 맞춘다.
- 골반을 모델의 로컬 축이 아닌 실제 수직 방향으로 내려 다리의 도달 범위를 확보한다. 보폭 끝에서 다리가 뻣뻣하게 펴지고 발이 밀리던 문제를 수정했다.
- 발의 왕복 궤적은 속도가 연결되는 곡선을 사용한다. 발목의 뒤꿈치·발끝 회전과 골반의 작은 상하 이동을 추가했다.
- 검격은 준비→뒤로 당기기→명중→후속 동작→복귀의 연속 곡선이다. 검의 방향은 방위각·고도각으로 보간해 방향 벡터가 상쇄되며 갑자기 빨라지는 구간을 제거했다.
- 손목에는 검 방향과 위쪽 기준으로 완전한 회전 좌표계를 지정한다. 최소 회전만 계산하던 손목이 반대 방향 근처에서 급격히 뒤집히는 문제를 수정했다.
- 제자리 공격은 오른발을 내딛고, 명중 구간에 지지한 뒤 회수한다. 실제 피해 시점은 영웅 0.26초, 수호병 0.18초로 유지한다. 적의 준비 자세와 마지막 명중 후 복귀를 연결한다.
- 이동 중 검격·뒤로 물러나며 공격·이동 중 회피, 두 손가락 조작, 정지·재시작을 지원한다. 회피·피격·사망은 기존 라이선스된 스킨 동작을 사용한다.

## 검증

`node scripts/verify_study.mjs`는 원본과 새 모델 SHA256, 실제로 참조되는 53관절 스킨, 정규화된 가중치, 재질 10개와 구운 조명 없는 자산을 검사한다. 기존 엔진 17개 검사와 원래 스킨/동작의 해시·가중치 검사도 통과했다.

`python scripts/verify_study_browser.py`는 Chromium에서 빠른 이동·느린 이동·후진 공격을 각각 360스텝 검증한다. 세 경우 모두 접지 표본 270개에서 수평 기준점 오차 0.001 월드 단위 미만, 접지 중 수평 이동은 수치 오차 수준이었다. 발바닥 최저 높이는 약 0.018, 최고 높이는 빠른 이동 약 0.160·느린 이동 약 0.090 월드 단위다.

검의 길이는 전체 공격에서 약 0.99 월드 단위로 일정하다. 명중 중 오른발의 수평 위치, 회전 상한, 정지·초기화, 첫 피해와 검격 정렬, 마지막 명중 후 복귀, 적 준비의 연속성, 실제 조명 반응과 자산 로딩 실패 UI를 검사했다. 실제 조명을 끄면 검사 장면의 캐릭터 밝기도 사라져 일러스트 고정 명암과 구분된다.

실제 키보드·바닥 탭·충돌·두 손가락 이동/공격·이동 중 회피·승리·다시 시작을 별도로 검사한다. 1024×768, 768×1024, 390×844에서 화면 스크롤 없이 조작할 수 있다.

검증은 Chromium 소프트웨어 WebGL에서 진행한다. 실제 iPad Safari의 프레임 속도 측정은 포함하지 않는다. 동작의 주관적인 품질과 최종 일러스트 아트 확정은 기능 QA와 별개의 검토 항목이다.

## 재현

실행에는 HTML/CSS·JavaScript·로컬 Three.js만 필요하다. 기존 체크아웃에서 별도 터미널로 `python -m http.server 8035 --bind 127.0.0.1`을 시작하고 `/study.html`을 연다. npm 설치나 빌드는 필요하지 않다. 아래 제작·검증 도구에는 Blender 4.3, Python NumPy/SciPy·Playwright, Chromium과 ffmpeg가 필요하다. 내부 서버 주소는 개발 검증용이며 공개 플레이는 위 Pages 주소를 사용한다.

```sh
blender -b -t 2 --python scripts/build_warden_character.py
node scripts/verify_study.mjs
STUDY_BASE=http://127.0.0.1:8035/study.html python scripts/verify_study_browser.py
ARENA_BASE=http://127.0.0.1:8035/study.html ARENA_VERSION=2.9 ARENA_SHOTS=docs/study-review-v2.9/game python scripts/verify_arena_browser.py
python scripts/render_study_motion.py
```

`render_study_motion.py`는 실제 훈련실과 같은 모델·재질·조명에서 한 방향의 232프레임을 계산한다. [동작 영상](../assets/study/motion-preview.mp4)은 60fps로 인코딩한 약 3.87초의 오프라인 렌더이며 실제 기기의 플레이 프레임 속도 녹화가 아니다. 렌더 영상의 그림자 맵은 768px, 플레이 장면은 2048px다. [접촉 시트](study-review-v2.9/motion-contact.png)는 같은 렌더를 HTML에서 배열한 검사 화면이다.
