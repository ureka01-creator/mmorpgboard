# 2.12 반복 QA와 동작 수정

승인된 2.8 PNG 10개와 warrior.json은 바꾸지 않는다. 캐릭터 얼굴·갑옷·비례·맵·카메라·전투 규칙을 유지한다. 이번 작업은 2.11의 검사 범위를 넓혀 실제 렌더에서 확인한 오류를 고친 것이다.

## 발견한 문제와 수정

- 보행의 각 원화 사이를 직선 변위로 연결해 경계에서 픽셀의 이동 속도가 갑자기 바뀌었다. 앞·뒤 변위장의 접선을 함께 읽는 Hermite 경로를 적용하고, 발·망토 끝이 자세 범위를 넘어가지 않게 접선을 제한한다. 이동 거리로 보행 주기를 정하는 규칙은 유지한다.
- 검을 분리하고 남은 빈자리를 다른 자세의 대응 픽셀로 채우다가, 관계없는 장화를 복사해 떠 있는 팔다리를 만들었다. 다른 자세의 복사를 제거하고 실제 몸 연결 영역으로 측정된 부분만 같은 원화의 몸 픽셀로 메운다. 기존 남서 방향 발 연결 검사도 유지한다.
- 가장 밝은 금속 직선을 검으로 선택하면 동쪽 준비 자세의 어두운 칼날 대신 어깨 갑옷을 선택했다. 어두운 강철도 탐색하고, 선 양옆에 배경이 드러나는 가늘고 긴 형태를 우선한다. 칼끝도 일정 픽셀만 늘리는 대신 실제 강철 영역을 따라 측정한다. 동쪽 준비와 북쪽 명중 자세에 원화 의미에 맞는 회귀 검사를 추가한다.
- 손잡이 뒤쪽으로 드러난 검의 일부가 몸에 남는 구간은 같은 검 레이어에 포함한다. 뒤쪽은 양옆이 비어 있는 강철 영역만 분리해 축 위의 갑옷이 검과 함께 회전하지 않게 한다.
- 검의 어두운 테두리까지 분리할 때는 기본 폭을 넓히되, 원래 몸의 연결을 끊는 자세는 좁은 폭을 유지한다. 동남 방향 복귀에서 발견한 126픽셀 다리 분리 회귀는 이 조건과 전체 공격 검사를 통해 막는다.
- 공격 시작은 대기에서 서서히 가속하고 마지막 복귀는 감속한다. 베기 중간 시점과 실제 피해 0.26초/0.18초는 유지한다.
- 피격 투명도에서 공격으로 바뀔 때 머리·검 레이어에 이전 투명도가 한 프레임 남는 것을 수정한다.

## 검사 방법

```sh
node scripts/verify_arena.mjs
node scripts/verify_motion.mjs
node scripts/verify_sprite_flow.mjs
ARENA_BASE=http://127.0.0.1:8037/ python scripts/verify_sprite_flow_browser.py
ARENA_BASE=http://127.0.0.1:8037/ python scripts/verify_attack_silhouette.py
ARENA_BASE=http://127.0.0.1:8037/ python scripts/verify_gait_continuity.py
ARENA_BASE=http://127.0.0.1:8037/ python scripts/verify_motion_browser.py
ARENA_BASE=http://127.0.0.1:8037/ ARENA_SHOTS=/tmp/elderfall-212-game python scripts/verify_arena_browser.py
ARENA_BASE=http://127.0.0.1:8037/ python scripts/verify_sprite_flow_loading.py
ARENA_ORIGIN=http://127.0.0.1:8037/ python scripts/verify_approved_art.py
```

별도 GPU 자세 검사는 준비된 게임의 원화/수치 데이터를 불러온 뒤 배경의 자동 렌더만 멈추고 검사 장면을 직접 렌더한다. 실제 입력 검사는 자동 렌더를 유지하고 기존의 실제 버튼·키보드·멀티터치로 수행한다. 소프트웨어 GPU에서 여러 무거운 브라우저를 동시에 실행하면 입력 대기가 시간 초과할 수 있으므로 GPU 검사는 순서대로 실행한다.

보행 경계 32곳에서 `sum(abs(next - 2*current + previous))`를 기존 직선 보간과 비교한다. 경계 앞뒤의 표본은 보행 한 프레임의 0.04 간격이며, 이 값은 화면 변화의 급격함을 보는 제한된 지표다. 자연스러움 점수로 해석하지 않는다.

공격은 8방향 × 31개 시점(0.02~0.62초)의 실제 GPU 알파 연결을 검사한다. 192×192 확대 화면에서 새로 떨어져 나온 큰 몸 조각을 막는 한도는 25픽셀이다. 이 검사는 앞선 66픽셀 장화 복사 문제를 검출하며, 작은 칼날 윤곽 조각까지 모두 없다는 뜻은 아니다. 기존 남서 방향 발 검사의 더 엄격한 한도는 변경하지 않는다.

## 시각 검토와 한계

`scripts/review_sprite_flow.py`로 [8방향 중간 자세](motion-review-v2.12/direction-0.png)를 렌더한다. 원화 자체의 팔다리·망토 형태 차이, 방향 교체와 이동/대기 전환의 자세 차이는 남는다. 망토는 별도 천 물리 시뮬레이션이 아니다. 자동 검증 통과를 완벽한 동작 판정으로 취급하지 않는다. 실제 iPad Safari 기기의 입력 지연·프레임 성능은 클라우드 Chromium 결과로 확정할 수 없다.

## 확인된 결과

- 17개 전투/이동 규칙과 원화·자세 데이터 해시 검사를 통과했다.
- GPU의 96개 보행 연결 검사에서 자세 교체 변화량 비율 중앙값은 0.21844, 원래 기준 자세의 정규화 채널 오차 최대는 0.021052였다. 남서 방향 발 연결의 추가 분리 픽셀은 0이었다. 피격에서 공격으로 전환하는 레이어 투명도 검사도 통과했다.
- 32개 보행 경계의 화면 2차 차분은 직선 보간 대비 평균 0.39906, 최대 0.85100이었다. 모든 표본에서 감소했다.
- 공격 248개 시점에서 추가 분리 픽셀 최대는 14였다. 수정 전 발견한 장화 복사 조각은 최대 66픽셀이었다. 이 서로 다른 수치를 품질 점수나 모든 조각의 완전 제거로 해석하지 않는다.
- 실제 키보드/탭 이동·충돌·멀티터치 공격·이동 중 회피·정지·초기화·5회 명중 승리와 1024×768, 768×1024, 390×844 화면 검사를 통과했다.
- 32개 바닥 깊이 사례, 기둥 가림, UV 독립성, 첫/마지막 타격, 적 준비 연결, 잘못된 데이터 재시도 UI 검사를 통과했다.
