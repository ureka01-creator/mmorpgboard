# 엘더폴 전면 개편 기획안

작성일: 2026-10-09. 현재 배포본 v0.6을 바꾸기 위한 **구현 전 기획안**이다. 아래 수치와 시간은 테스트용 가설이며, 현재 게임에 적용된 규칙이 아니다.

## 1. 게임의 정체성과 범위

**아이패드 한 대를 가운데 두고, 영웅을 성장시켜 제한된 시간 안에 대형 보스를 공략하는 협동 모험 보드게임.** 1~4명이 기기를 넘겨 사용한다. 서양 판타지의 기사·마법사·사냥꾼·사제로 출발한다.

2005년 FFG 《월드 오브 워크래프트 보드게임》에서 참고하는 축은 넓은 세계의 지역 이동, 퀘스트를 통한 성장, 직업별 기술과 장비에 따른 전투 구성, 제한된 시간에 무엇을 준비할지 결정하는 긴장감이다. 그 작품의 정확한 규칙을 재현한다는 뜻은 아니다. 이번 개편은 협동 게임으로 설계하며 진영 경쟁은 별도 확장 후보로 둔다. 원작의 이름·그림·캐릭터·카드 문구는 사용하지 않는다.

목표 체험 길이는 입문 전투 5~8분, 짧은 모험 20~30분, 본 캠페인 60~90분이다. 실제 플레이로 검증한 뒤 조정한다. 온라인 멀티플레이, 계정, 대규모 콘텐츠 제작은 첫 구현 범위에서 제외한다.

## 2. 재미의 구조와 캠페인 흐름

지금은 이동과 수치 증가가 다음의 비슷한 전투로 이어진다. 개편에서는 **목표 선택 → 위험과 비용을 따진 여행 → 주사위 운용 전투 → 성장 선택 → 달라진 전략으로 다음 목표 도전**이 연결되어야 한다.

| 단계 | 플레이어의 선택 | 다음 단계에 미치는 영향 |
| --- | --- | --- |
| 모험 준비 | 직업과 시작 기술 구성 | 공격·보호·회복 역할과 첫 전투의 선택지 |
| 목표 선택 | 장비 보상, 기술 해금, 세계 위협 감소 중 우선순위 | 이동 경로와 준비해야 할 전투 |
| 여행 | 안전한 우회 또는 보급을 쓰는 지름길 | 남은 시간·체력·보급 |
| 전투 | 재굴림, 기술에 주사위 배치, 동료 보호 | 승률·소모 자원·다음 전투의 준비 상태 |
| 보상 | 새 기술 또는 장비 중 빌드에 맞는 선택 | 이후 사용하는 기술 조합과 주사위 구성 |
| 최종 공략 | 일찍 도전 또는 추가 준비 | 세계 위협과 파티 전력 사이의 타협 |

세계 위협은 일정 라운드마다 진행하는 공개 트랙으로 보여준다. 단순히 마지막에 시간이 끝나는 대신 특정 단계에서 위험 지역 강화나 보급 감소가 예고된다. 상세 주기와 페널티는 짧은 모험을 검증한 다음 정한다. 전투 안의 교전 횟수와 세계 라운드는 명확히 구분한다.

완료 기준: 첫 목표를 선택할 때 서로 다른 보상의 가치가 보이고, 성장 후 이전과 다른 기술 선택이 실제로 유리해지는 상황이 존재해야 한다.

## 3. 시작 화면과 규칙 안내

첫 화면의 주인공은 세계관 설명문보다 **무슨 게임인지와 어떻게 시작하는지**다. 큰 세계 삽화, 한 문장 게임 설명, 예상 시간·인원, `전투 체험`과 `새 모험`을 배치한다. 저장 기록이 있으면 `모험 계속`을 가장 먼저 제공한다.

직업 선택은 초상·역할·대표 기술·난이도를 한 카드에 보여준다. 예: 기사 “동료를 보호하고 반격하는 전열”, 마법사 “마법 주사위를 모아 폭발적인 피해”. 기술 세부 설명은 누르면 펼친다.

입문은 실제 전투를 통해 적의 다음 공격 확인, 주사위 굴리기, 기술에 배치, 결과 확정 순으로 안내한다. 긴 규칙을 먼저 읽게 하지 않는다. 연습 전투는 캠페인 저장을 덮어쓰지 않는다.

완료 기준: 처음 접한 사람이 설명을 듣지 않고 게임 목표와 첫 조작을 찾을 수 있어야 한다.

## 4. 탐험 화면과 지도

가로 아이패드 화면을 주 기준으로 잡는다. 상단에는 현재 영웅·남은 행동·세계 위협만 짧게 표시한다. 중앙의 가장 넓은 영역은 지도다. 오른쪽에는 선택한 지역 카드, 아래에는 파티 토큰과 현재 가능한 행동을 둔다. 지역을 누르면 이동 비용과 목적을 확인하고 확정한다.

지도에는 연결된 길, 지역 난이도, 퀘스트 표식, 적 미니어처, 파티 위치를 보드 위의 구성물처럼 표현한다. 풍경 그림 위에 정보가 섞이지 않도록 길과 토큰의 명도·테두리를 분리한다. 이동할 수 없는 지역은 조건을 적는다. 예: “산길 진입: 레벨 2 필요”.

지역 카드는 이름, 방문 목적, 적/퀘스트, 이동 비용, 가능한 행동 순서다. 선택 지역이 없을 때에는 추적 중인 목표를 보여준다. 안전 경로와 빠른 경로는 선택한 목적지에 대해서만 비교한다. 이동 중간의 휴식·구매까지 자동 계획하지 않는다.

완료 기준: 1024×768 가로 화면에서 지도·현재 목표·행동 버튼이 동시에 보이고 페이지 스크롤 없이 한 차례를 진행할 수 있어야 한다. 세로 화면은 지도와 접이식 지역 카드로 재배치한다. 작은 휴대전화에서는 정보 패널 내부 스크롤을 허용하되 핵심 행동은 고정한다.

## 5. 퀘스트와 여행의 의미

퀘스트는 체크리스트를 넘어 **어떤 성장을 먼저 얻을지 정하는 선택**이 되어야 한다. 추적할 목표 하나를 지도에 표시하고, 퀘스트 카드에는 목적지·조건·보상·대략적인 위험을 적는다. 초기에는 동시에 보유할 수 있는 수를 적게 유지한다.

첫 짧은 모험에는 세 종류를 넣는다: 안전한 수집으로 자원 마련, 위험한 사냥으로 공격 장비 획득, 먼 거점까지 호위해 지원 기술 해금. 동일한 목표라도 파티 구성에 따라 우선순위가 달라지게 한다. 자원 확보만 반복하는 사냥은 피한다.

보급은 위험 경로와 야외 휴식에 쓰고, 골드는 장비와 소모품에 쓴다. 각 자원의 사용 목적을 화면에서 설명한다. 세계 위협이 진행되기 때문에 무한히 회복하거나 쇼핑할 수 없다.

완료 기준: 짧은 모험에서 안전한 우회와 보급 지름길 양쪽에 실제로 선택할 이유가 있고, 목표 변경의 비용을 판단할 수 있어야 한다.

## 6. 전투 규칙 — 첫 번째 구현의 중심

전투는 **적 행동 확인 → 준비 → 주사위 굴림 → 재굴림·기술 배치 → 실행 → 적 반격 → 다음 교전**으로 진행한다. 다음 공격과 대상은 준비 단계부터 공개한다. 플레이어는 공격만 누르지 않고 이번 교전에서 피해를 줄지, 보호할지, 자원을 아낄지 결정한다.

### 주사위와 기술 배치

공격·마법·방어 주사위의 기본 성공 규칙은 출발점으로 활용한다. 굴린 주사위를 그대로 쓰면 기본 공격 또는 방어에 기여한다. 기술 카드에 배치하면 해당 주사위의 기본 기여를 소비하고 기술 효과를 얻는다. 같은 주사위를 두 기술이나 기본 공격에 중복 계산하지 않는다.

기술에는 필요한 색·눈 조건·주사위 수, 추가 에너지 비용, 효과, 사용 후 재사용 대기를 표시한다. 예를 들어 기사의 `방패 반격`은 방어 주사위 하나를 배치해 보호와 반격을 얻고, `강타`는 높은 공격 눈 하나를 배치해 갑옷을 일부 무시한다. 이는 효과 구조의 예시이며 피해 수치는 시뮬레이션 후 확정한다.

기술을 선택하면 사용 가능한 주사위를 강조한다. 주사위를 누르는 방식으로 배치하며, 드래그는 선택적인 편의 기능이다. 배치는 실행 전 취소할 수 있다. 자원 소비와 피해 반영은 실행 확정 시 한 번만 발생한다. 재굴림은 별도 모드에서 선택한 주사위에 적용해 배치 조작과 충돌하지 않게 한다.

화면에는 현재 배치에 따른 예상 피해·보호·회복과 적 반격 후 예상 체력을 표시한다. 결과에 아직 무작위 요소가 남아 있으면 확정 수치처럼 표시하지 않는다. 실행 전 후퇴 가능 여부도 명시한다.

### 직업별 선택

| 직업 | 기본 전투 성격 | 첫 기술 구성의 방향 | 성장 후 달라지는 선택 |
| --- | --- | --- | --- |
| 기사 | 전열 보호와 물리 공격 | 강타 / 동료 보호 / 방패 반격 | 버티며 반격 또는 갑옷 관통에 집중 |
| 마법사 | 자원 관리와 마법 폭발 | 화염탄 / 둔화 / 마력 전환 | 연속 시전 또는 큰 기술을 위한 준비 |
| 사냥꾼 | 눈 조정과 표적 공략 | 정밀 사격 / 함정 / 추적 | 치명타 집중 또는 적 행동 제어 |
| 사제 | 회복과 지원 공격 | 치유 / 보호막 / 심판 | 동료 지원 또는 회복과 공격의 연계 |

첫 전투 체험은 기사 기술 세 개와 적 하나만으로 검증한다. 이후 네 직업으로 확장한다. 신규 기술 해금 후 사용할 기술을 제한된 슬롯에 장착하도록 하여, 카드 수가 늘어나는 것이 실제 구성 선택으로 이어지게 한다. 슬롯 수와 교체 조건은 체험 결과로 정한다.

### 적의 차이

늑대는 공격 예고와 방어의 기본을 가르친다. 트롤은 재생 때문에 공격 집중이나 회복 차단을 요구한다. 망령은 방어 특성 때문에 물리·마법 구성 선택을 요구한다. 용은 단일 공격과 광역 공격의 주기를 보고 파티 보호 자원을 준비하게 한다. 적마다 체력 수치만 바뀌는 구성을 피한다.

협동에서는 각 영웅의 주사위 소유권과 기술을 구분하며, 동료 보호·치유 대상 선택을 제공한다. 1인도 생존과 공격 사이에서 선택할 수 있어야 한다. 인원별 적 체력만 늘리는 방식의 한계는 별도 밸런스 테스트에서 확인한다.

완료 기준: 같은 주사위 결과에서 공격 집중과 생존 중심 배치가 모두 유효하고, 실패한 눈에도 최소 하나의 활용 선택이 있어야 한다. 자동으로 가장 큰 공격 기술만 쓰는 것이 항상 정답이면 기술 구성을 다시 설계한다.

## 7. 전투 화면과 연출

탐험에서 전투로 화면을 전환한다. 상단은 적 초상·체력·방어 특성·다음 행동, 중앙은 주사위 테이블, 하단은 현재 영웅의 기술 카드와 실행 버튼이다. 파티는 작은 초상과 체력으로 표시하며 선택한 영웅의 기술을 펼친다. 큰 인물 그림이 조작 공간을 밀어내지 않게 한다.

주사위는 숫자 사각 버튼 대신 여섯 면과 눈이 있는 입체 주사위로 표현한다. 색 외에 문양으로 공격·마법·방어를 구분한다. 굴림 → 멈춤 → 선택 가능 상태가 시각적으로 구분되고, 배치한 주사위는 기술 카드 슬롯에 들어간다. 터치 영역은 최소 44px을 목표로 한다.

연출 순서는 주사위 굴림, 기술 활성화, 공격 적중, 적 체력 감소, 반격, 영웅 체력 변화다. 짧은 카메라 효과·카드 발광·피해 숫자로 원인을 전달한다. 최초 조작 후 켤 수 있는 소리와 음소거, 연출 빠르게 보기, 동작 줄이기를 제공한다.

규칙 계산은 연출과 분리한다. 실제 결과를 먼저 확정·저장하고 표시만 단계적으로 진행해, 중복 터치나 새로고침으로 피해가 두 번 적용되지 않게 한다. CSS 입체 표현으로 먼저 구현하며 물리 엔진의 필요성은 실물감 검증 후 판단한다.

완료 기준: 주사위 눈을 바로 읽을 수 있고, 어떤 기술이 얼마의 피해를 줬는지 추적할 수 있어야 한다. 연출을 끄거나 도중에 새로고침해도 규칙 결과가 같아야 한다.

## 8. 보상·성장·장비 화면

승리 후 별도 보상 화면에서 기여한 영웅의 경험치와 획득 보상을 보여준다. 장비 후보는 비교 카드로 제시하고, 현재 장비와 바뀌는 주사위·기술 효과를 함께 표시한다. “공격 +1”보다 “공격 주사위 하나 추가, 강타에 쓸 기회 증가”처럼 선택의 영향을 설명한다.

성장 화면은 직업 기술, 특성, 장착 슬롯을 한곳에 모은다. 새 기술 해금과 현재 장착 기술 교체를 구분한다. 장비는 기술과 연결되는 효과를 점진적으로 넣되 첫 체험에서는 복잡한 옵션을 억제한다. 레벨 숫자만 올라가는 성장은 피한다.

파티 현황에서는 역할·체력·준비 상태를 비교하고 같은 지역에서 장비를 전달한다. 상점은 지역 행동에서 열고 구매 전에 비용과 사용 목적을 보여준다.

완료 기준: 보상 선택 전에 무엇이 달라지는지 알 수 있고, 성장 후 다음 전투에서 새 기술을 실제로 사용할 수 있어야 한다.

## 9. 시각 디자인과 상황별 UI

세계 지도는 보드, 영웅과 적은 토큰·미니어처, 기술과 장비는 카드, 시간과 자원은 트랙과 칩으로 표현한다. 기존 판타지 일러스트는 재사용 가능하지만 구도에 맞지 않는 그림은 교체한다. 모든 패널에 장식을 늘리기보다 보드·카드·토큰의 재질과 그림자 기준을 먼저 통일한다.

색은 짙은 석재 배경, 밝은 양피지 카드, 제한된 금속 강조색을 기준으로 삼는다. 본문 대비와 글자 크기를 먼저 확보한다. 선택·사용 가능·조건 부족·소모·대기 상태를 일관되게 표현하고 조건 부족의 이유는 터치로 확인한다. 도움말은 해당 행동 옆에 제공한다.

사용자가 말한 Intelligent UI 글은 ChatGPT 대화 화면의 기능을 설명한다. 현재 개발 환경에서 그 기능을 호출하는 도구는 확인되지 않았다. 이 게임에서는 **탐험·전투·보상 상황에 필요한 정보와 행동을 보여주는 화면**으로 요구를 구현한다. 특정 ChatGPT 기능을 웹게임에 탑재했다고 표현하지 않는다.

완료 기준: 실제 아이패드 크기의 탐험·전투·보상 시안 세 장을 먼저 비교하고, 장식이 텍스트·조작 영역을 침범하지 않아야 한다. 키보드 초점·색 이외 상태 표시·동작 줄이기도 검증한다.

## 10. 제작 순서와 검증

| 순서 | 제작 범위 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 1. 화면 시안 | 탐험·전투·보상 세 화면, 카드·토큰·주사위 스타일 | 화면 구성과 정보 우선순위를 실제 크기로 검토 |
| 2. 전투 체험 | 기사 1명, 적 1종, 기술 3개, 재굴림·배치·연출 | 5~8분 체험에서 서로 다른 유효 선택과 읽기 쉬운 결과 |
| 3. 짧은 모험 | 작은 지역 묶음, 퀘스트 3개, 보상·기술 성장 | 여행→전투→성장→재전투가 전략을 바꾸는지 확인 |
| 4. 협동과 확장 | 네 직업, 지원 대상 선택, 기존 지도·보스 연결 | 1~4인 난이도·대기 시간·지원 역할 검증 |
| 5. 공개 교체 | 저장 이관, 전체 QA, Git 업로드·배포 | 기존 기록 보호와 공개 주소에서 전체 플레이 확인 |

기능 QA는 주사위 중복 사용 방지, 잘못된 비용·대상 거부, 미리보기와 실제 결과 일치, 쿨다운, 소유권, 승리·패배·후퇴, 저장 복원, 연속 터치 방지를 검사한다. 터치 브라우저 검사는 실제 행동을 통해 탐험부터 보상까지 진행하고 가로·세로 화면의 넘침과 버튼 접근성을 검사한다. 실제 iPad Safari 검증 여부는 별도로 기록한다.

재미 검증은 기능 검사와 분리한다. 전투 체험 뒤에는 “왜 그 기술을 골랐는가”, “다음에는 다른 선택을 해보고 싶은가”, “결과의 원인을 이해했는가”를 확인한다. 전투 길이·선택 없이 실행한 교전·항상 선택되는 기술·동료 대기 시간도 관찰한다. 기능 검사가 통과했다는 이유로 재미가 완성됐다고 발표하지 않는다.

수치 시뮬레이션은 공격 중심·생존 중심·상황 대응 정책을 비교한다. 좋은 고정 주사위만으로 난이도를 판단하지 않는다. 승률 목표는 체험 피드백 뒤 정하고 기술 비용·적 패턴을 조정한다.

기존 v0.6과 새 규칙은 분리된 저장 키를 사용한다. 기존 기록을 백업하고 새 캠페인을 시작할 수 있게 하며, 진행 중인 구형 전투를 새 기술 전투로 무리하게 변환하지 않는다. 이관할 수 있는 필드와 불가능한 필드를 정한 후 구현하고 사용자에게 안내한다. 연습 전투는 별도 상태를 사용한다.

### 첫 구현 범위와 아직 확정하지 않은 사항

첫 구현은 **화면 시안 세 장과 기사 전투 체험**까지다. 전체 직업 카드·지도·캠페인 숫자를 동시에 바꾸지 않는다. 짧은 전투에서 선택과 조작이 성립한 다음 나머지 섹션을 연결한다.

아직 확정하지 않은 것은 기술 슬롯 수, 개별 효과와 비용, 위협 트랙 주기, 캠페인 목표 시간과 인원별 난이도다. 이 항목은 테스트를 통해 결정한다. 진영 경쟁을 원한다면 협동 캠페인과 다른 목표·상호작용·밸런스가 필요하므로 이후 별도 기획으로 다룬다.
