# 2.0 첫 던전 범위

녹스의 높은 시점과 직접 조작하는 실시간 액션을 참고한다. 하나의 성역 방과 연결 통로에서 기사가 직접 이동하고, 수호병의 추격/공격 준비를 보고 검격과 회피로 싸운다. 왼쪽 이동 패드, 오른쪽 검격·회피, PC 키보드와 바닥 탭을 지원한다. 자동 접근·턴·조건부 자동 반격은 제거한다. 성인 비례 관절 모델과 던전 아트를 새로 구성하되 목표 시안과 실제 렌더를 구분한다.

첫 범위에서 인벤토리·마법·퀘스트·파티·저장·문 상호작용·다음 구역 전환은 보류한다. 실시간 충돌/명중/회피/정지/중복 입력, 태블릿 두 손가락 조작을 먼저 검증한다.

# 실제 3D RPG 제작 방향

사용자가 선택한 방향은 실제 3D 공간과 움직이는 캐릭터다. 현재 범위는 이동과 공격까지만 완성한 뒤 다음 기능을 붙이는 것이다.

## 1. 첫 제작 단위: 이동과 공격

작은 유적 하나, 기사 한 명, 수호병 한 명으로 제한한다. 바닥 탭 → 실제 경로를 따라 걷기 → 적 탭 → 사거리까지 접근 → 검격 → 타격 시점에 피해 → 피격/쓰러짐이 연결되어야 한다. 카메라를 회전·확대해 3D 공간을 볼 수 있어야 한다. 중복 입력으로 공격이 중첩되어서는 안 된다.

1.1은 이 흐름을 실제 WebGL과 스키닝 애니메이션으로 확인하는 동작 검증판이다. 정교한 아트의 완료를 의미하지 않는다. 바닥과 장애물이 시각/규칙에서 일치하고 경로를 가로질러 순간이동하지 않는지 우선 점검한다.

## 2. 아트 기준

[목표 시안](screenshots/3d-target-concept.png)의 석조 유적, 인체 비례와 갑옷, 명확한 이동 경로, 절제된 UI를 참고한다. 이 이미지는 실제 게임 화면이 아니다. 임시 KayKit 모델과 프로그래밍한 환경을 사실적인 목표 아트로 교체하려면 이에 맞는 모델·재질·리깅·애니메이션을 제작/확보해야 한다. 시안 생성과 실제 3D 자산 제작을 같은 작업으로 취급하지 않는다.

## 3. 이후로 미룬 시스템

이동과 공격의 공간감·동작·반응·입력이 안정된 뒤에 동료, 대화 선택, 턴과 행동력, 조사와 임무, 장비와 성장, 저장을 차례로 설계한다. 지금 화면에는 미구현 기능 메뉴를 추가하지 않는다.

## 4. 검증 기준

경로와 장애물, 사거리, 타격 시점, 피해 상한, 생존 적의 반격, 사망 동작과 재시작을 확인한다. 모델 뼈대의 포즈가 실제로 바뀌는지 검증한다. 태블릿 화면과 터치 입력을 확인하되 Chromium 검증을 iPad Safari 실기기 확인으로 대신하지 않는다. 품질 결함과 아트 작업 기준은 [품질 점검](quality-review.md)에 기록한다.
