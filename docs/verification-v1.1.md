# 3D 이동·공격 1.1 검증

2026-10-11 · Node 24 · Python Playwright + Chromium의 SwiftShader WebGL.

## 규칙

`node scripts/verify_arena.mjs`: 7개 테스트 통과.

- 경로는 경계와 장애물·살아 있는 적의 칸을 통과하지 않는다.
- 대각선 이동으로 기둥 모서리를 관통하지 않는다.
- 막힌 칸·범위 밖 이동과 사거리 밖 공격은 상태를 변경하지 않는다.
- 접근 경로는 적의 칸을 점유하지 않고 공격할 수 있는 거리에서 끝난다.
- 검격마다 피해 6, 살아 있는 적의 반격마다 피해 4. 네 번의 공격으로 수호병이 쓰러지며 죽은 적은 반격하지 않는다.
- 내비게이션 좌표와 실제 3D 바닥 좌표가 왕복 변환에서 일치한다.

## 실제 렌더링과 입력

`python scripts/verify_arena_browser.py`에서 실제 WebGL 장면과 GLB skin/애니메이션을 실행했다. 정지 이미지를 이동시킨 화면을 테스트한 것이 아니다.

1024×768에서 다리 뼈대의 quaternion이 걷기 중 변하는 것을 확인했다. 실제 바닥 터치로 이동하고 기둥 안을 누르면 이동하지 않는다. 카메라 회전은 플레이 상태를 변경하지 않는다. 회전 직후 선택 좌표가 어긋나던 문제를 발견해 projection과 raycasting 전에 카메라 행렬을 갱신했다.

실제 적 선택 영역을 터치해 접근 → 걷기 → 검격을 실행한다. 검이 닿기 전에는 체력이 줄지 않고 타격 프레임에 피해가 반영된다. 동작 중 추가 클릭은 공격 횟수나 피해를 중복 생성하지 않는다. 피격·반격·사망 동작, 피해 상한, 승리 후 공격 비활성화, 다시 시작과 취소를 확인했다.

768×1024와 390×844에서도 화면 전체 스크롤 없이 하단 조작을 사용할 수 있고 실제 접근·공격으로 적의 체력이 줄어든다. 세로 화면에서는 기사에서 시작해 이동 중 카메라가 따라간다. 행동 버튼 높이는 44px 이상이다. 브라우저 실행 오류나 자산 HTTP 오류가 없는지 확인한다.

## 공개 검증

`python scripts/verify_public.py`는 실제 공개 HTTPS 파일의 SHA256을 소스와 비교한 뒤 그 파일 그대로 WebGL/스키닝, 터치 이동, 접근, 검격·반격과 사망을 실행한다. 클라우드 Chromium의 프록시 CA 저장소를 우회해 TLS 검증을 끄는 대신, 시스템 신뢰 저장소로 HTTPS를 검증한 응답을 전달한다.

2026-10-11 실행 결과: 공개 파일 24개가 소스와 일치하고 JavaScript 모듈의 MIME 형식도 정상이다. 실제 공개 응답으로 이동과 네 번의 공격·반격·사망을 완료했다. GitHub Pages 실행 `38118267712`가 성공했으며 배포 커밋은 `563f648afef09ec8203177d1bb2e300d6eb350e8`, 게임 소스 커밋은 `a7bec16`이다. 주소: https://ureka01-creator.github.io/mmorpgboard/?release=1.1

## 확인하지 않은 것과 품질 범위

실제 iPad Safari, 해당 기기의 GPU 프레임률·배터리·절전 후 복원은 확인하지 않았다. SwiftShader 기능 검증을 실제 기기의 성능 검증으로 간주하지 않는다.

현재 장면은 이동과 공격의 토대다. 모델은 임시 KayKit 스타일의 자산이고 환경은 코드로 구성한 테스트 유적이다. 이미지 생성으로 만든 목표 시안의 사실적인 아트 수준을 구현한 버전은 아니다. 대화·동료·퀘스트·장비·저장·주사위 전투는 현재 범위에 없다. 이전 2D 시제품의 검증은 [별도 과거 기록](verification-v1.0.md)에 남겼다.
